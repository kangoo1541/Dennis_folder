# SW 엔지니어 성장 커리큘럼

> 굴착기 유압성능 개발자 → **임베디드/제어 소프트웨어 엔지니어**
> 강사: Claude · 수강생: 1명 (나)

---

## 0. 왜 이 방향인가요?

소프트웨어 엔지니어의 길은 여러 갈래(웹, 앱, AI, 임베디드 …)입니다.
그중 **임베디드/제어 SW** 를 첫 목표로 잡은 이유는 세 가지입니다.

| 내가 이미 가진 것 | 임베디드 SW 에서 어떻게 쓰이나 |
|---|---|
| 유압 회로, 펌프·밸브 동작 이해 | 굴착기 제어기(MCU) 가 "무엇을" 제어하는지 이미 앎 |
| 성능 시험, 데이터 측정 경험 | 센서 신호 처리, 로깅, 데이터 분석 도구 개발 |
| STM32F411 공부 중 | 바로 그 다음 단계로 이어짐 |

> 비유: 신입 SW 개발자는 "코드는 알지만 굴착기를 모르는" 상태입니다.
> 나는 반대로 "굴착기는 알지만 코드를 배우는" 상태입니다.
> 두 가지를 다 가진 사람은 회사 안에서 매우 드뭅니다. 그게 나의 무기입니다.

## 2. Phase 별 상세

### Phase 0 · 개발자의 도구 (2주)
SW 개발자가 매일 쓰는 도구를 손에 익힙니다. 코드보다 먼저입니다.

| 주차 | 주제 | 실습 |
|---|---|---|
| W01 | 터미널과 Git 기초 | 공부 일지 저장소에 첫 커밋 |
| W02 | 브랜치 · Pull Request · 코드 리뷰 받기 | 과제를 PR 로 제출하고 리뷰 받기 |

**졸업 과제**: 브랜치를 만들어 과제를 올리고, 리뷰 반영 후 머지까지 혼자 하기

### Phase 1 · C 언어 탄탄히 (6주)
"동작하는 코드"에서 "왜 동작하는지 아는 코드"로 넘어갑니다.

| 주차 | 주제 | 굴착기 비유 |
|---|---|---|
| W03 | 변수 · 자료형 · 메모리 크기 (`uint8_t`, `int32_t`) | 배관 굵기마다 흘릴 수 있는 유량이 다르다 |
| W04 | 포인터 | 기름 자체가 아니라 "탱크 위치"를 알려주는 것 |
| W05 | 배열 · 문자열 · 구조체 | 실린더 1개의 사양서 = 구조체 |
| W06 | 함수 포인터 · 콜백 | CLI 명령어 테이블이 바로 이것 |
| W07 | 비트 연산 · `volatile` · `static` | 밸브 8개 ON/OFF 를 1바이트로 표현 |
| W08 | 빌드 과정 (전처리 → 컴파일 → 링크) · Makefile | 부품 가공 → 조립 → 완성차 |

**졸업 과제**: 굴착기 센서 데이터(압력·각도) 구조체를 만들고, 바이트 배열로 변환/복원하는 함수 작성

### Phase 2 · MCU 와 친해지기 (6주)
HAL 함수 뒤에 숨어 있는 진짜 하드웨어 동작을 이해합니다.

| 주차 | 주제 |
|---|---|
| W09 | 데이터시트·레퍼런스 매뉴얼 읽는 법, 메모리 맵 |
| W10 | 레지스터로 GPIO 직접 제어하기 (HAL 없이) |
| W11 | 인터럽트와 NVIC — "폴링 vs 인터럽트" |
| W12 | 타이머 · PWM — 비례 밸브 구동 신호 만들기 |
| W13 | ADC — 압력 센서 전압 읽기 |
| W14 | DMA — CPU 를 쉬게 하는 법 |

**졸업 과제**: 가변저항(=조이스틱 대용) 값을 ADC 로 읽어 PWM 듀티로 출력하고, CLI 로 확인

### Phase 3 · 설계하는 습관 (4주)
혼자 짠 코드가 아니라 "팀이 읽을 수 있는 코드"를 만듭니다.

| 주차 | 주제 |
|---|---|
| W15 | 계층 구조 (ap / hw / bsp) 다시 보기 · 인터페이스 설계 |
| W16 | 상태머신 — 굴착기 작업 모드(대기/굴착/선회/주행) 구현 |
| W17 | 링버퍼 · 큐 — 데이터가 몰려도 잃어버리지 않기 |
| W18 | PC 에서 단위 테스트 하기 (Unity 프레임워크, 시뮬레이터) |

**졸업 과제**: 작업 모드 상태머신을 만들고, PC 에서 테스트 10개 이상 통과

### Phase 4 · 통신과 RTOS (6주)
실제 건설기계는 제어기 여러 개가 CAN 으로 대화합니다.

| 주차 | 주제 |
|---|---|
| W19 | 통신 프로토콜 설계 (패킷 · 체크섬 · CRC) |
| W20 | CAN 기초 — 프레임 구조, ID, 중재 |
| W21 | CAN 실습 — STM32 두 대 또는 루프백 모드 |
| W22 | J1939 맛보기 — 건설기계/상용차 표준 |
| W23 | RTOS 개념 — 태스크 · 스케줄러 · 우선순위 |
| W24 | FreeRTOS 실습 — 큐 · 세마포어 · 뮤텍스 |

**졸업 과제**: 센서 태스크 → 큐 → 통신 태스크 구조로 데이터를 주기 송신

### Phase 5 · 도메인 프로젝트 (6주)
내 전공(유압)과 새 기술(SW)을 합친 **포트폴리오 대표작**을 만듭니다.

| 주차 | 주제 |
|---|---|
| W25 | 제어 이론 복습 — P / PI / PID, 이산화 |
| W26 | 유압 실린더 간이 모델을 C 로 시뮬레이션 |
| W27 | PID 로 실린더 위치 제어 — 시뮬레이터에서 튜닝 |
| W28 | 같은 코드를 STM32 로 이식 (PWM 출력 · ADC 피드백) |
| W29 | Python 으로 로그 분석 · 그래프 도구 만들기 |
| W30 | 문서화 · 데모 영상 · 회고 |

**졸업 과제**: "실린더 위치 제어 시뮬레이터 + 분석 도구" 저장소 공개

### Phase 6 · 포트폴리오와 커리어 (3주)

| 주차 | 주제 |
|---|---|

## 3. 수업 방식

```
① 레슨 읽기        study/lessons/Wxx-*.md  (개념 + 비유 + 예제)
② 따라 치기        예제 코드를 직접 타이핑하고 실행
③ 과제 제출        study/homework/Wxx/ 에 코드 올리고 커밋
④ 강사 리뷰        Claude 에게 "Wxx 과제 리뷰해줘"
⑤ 질문 · 복습      모르는 건 언제든 질문 → 이해될 때까지
```

**규칙 세 가지**
1. 예제는 복사-붙여넣기 하지 말고 **직접 타이핑**합니다. 손이 기억합니다.
2. 막히면 30분 고민 후 질문합니다. 고민한 흔적(에러 메시지, 시도한 것)을 같이 보여 주세요.
3. 매주 끝에 `study/homework/LOG.md` 에 **3줄 회고**를 씁니다. (배운 것 / 어려운 것 / 다음 주 목표)

**강사에게 말하는 법 (예시)**
- `W01 시작하자` → 해당 주차 수업 진행
- `W03 과제 리뷰해줘` → 제출한 코드 리뷰
- `포인터가 이해가 안 돼, 다르게 설명해줘` → 다른 비유로 재설명
- `퀴즈 내줘` → 복습 문제 출제
